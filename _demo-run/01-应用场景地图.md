## 二、★ 优先落地（4 个，第一阶段立即启动）

### S-01 经营日报自动化
| 字段 | 内容 |
|---|---|
| 业务痛点 | 现在集团日报靠 6 家市场**手工报 Excel**，汇总需 2 人半日；数据常 T+3 才齐 |
| 数据方案 | 交易结算系统 + 进场登记；走已建的采集层（**替代 7 处手工断点中的 4 处**） |
| 价值类型 | 降本 + 增效 |
| 价值量化 | 汇总人力从 **2 人半日 → 自动生成**；时效 **T+3 → T+1**（量级口径，年化节约人力约百人日级） |
| 可行性 | **高**——数据已在系统内，采集层一期在建 |
| 前置条件 | 采集层一期完成；交易额口径按 `M-001` 统一 |
| 归属工序 | **用** |

### S-02 市场价格监测预警
| 字段 | 内容 |
|---|---|
| 业务痛点 | 价格异常（暴涨暴跌）事后才知；各市场单位不统一（**实测 2 个市场用元/斤**），横向对比失真 |
| 数据方案 | 价格明细表（`M-002` 日均价口径）+ 质量规则集的价格波动规则 |
| 价值类型 | 风控 + 对外影响力 |
| 价值量化 | 异常发现时效 **事后 → 当日**；**为后续价格指数打基础** |
| 可行性 | **中高**——需先修单位不统一（质量阶段已识别） |
| 前置条件 | 单位统一整改完成；行情系统确立为唯一权威源 |
| 归属工序 | **用 + 模**（预警规则属模） |

### S-03 商户统一视图（One ID）
| 字段 | 内容 |
|---|---|
| 业务痛点 | 同一商户在交易/服务 App/财务**三套 ID**；无法判断商户真实经营画像 |
| 数据方案 | 建 `商户统一编码`；打通三系统（主数据方案已出，待实施） |
| 价值类型 | 增效 + 为后续变现奠基 |
| 价值量化 | 商户画像从"看不清"→"可分析"；**是所有对外数据产品的必要前置** |
| 可行性 | **中**——技术上明确，但需三系统协同改造 |
| 前置条件 | 主数据方案实施；架构二期治理层落地 |
| 归属工序 | **治 + 管**（跨工序，主数据属治） |

### S-04 集团经营驾驶舱
| 字段 | 内容 |
|---|---|
| 业务痛点 | 董事长要看跨市场对比，现有报表口径不一致，会上常被质疑数字 |
| 数据方案 | 交易/商户/价格/物流四域指标，**全部走指标字典统一口径** |
| 价值类型 | 增效 + 决策质量 |
| 价值量化 | **口径争议当场消解**（指标字典已覆盖 10 个核心指标） |
| 可行性 | **中高**——口径已统一，数据已具备 |
| 前置条件 | 指标字典 Owner 签字确认完成 |
| 归属工序 | **用** |

## 四、⚠️ 战略储备（3 个，中远期）

| 编号 | 场景 | 为什么价值高 | 为什么现在难 | 前置条件 |
|---|---|---|---|---|
| T-01 | **行业价格指数发布** | 一旦成为行业指数，**掌握定价话语权**（呼应"成为行业核心数据源"主线） | 需跨区域数据接入 + 方法论 + 公信力建设 | 价格数据治理完成 + 跨区域数据源 + 指数方法论 |
| T-02 | 供应链金融服务 | 数据→信用→金融，**想象空间最大** | 涉及金融牌照、商户隐私、资金方对接 | 商户画像（S-03）+ 合规框架 + 资金方 |
| T-03 | 跨区域产销匹配 | 撮合价值高 | 需接入产区数据，非本集团控制 | 跨区域数据合作 |

> **T-01 是本集团的战略主线**——直接对应"能否成为行业核心数据源"。

| 编号 | 场景 | 不做的原因（**汇报时必须能答**） |
