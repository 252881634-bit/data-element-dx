## 〇、为什么分两类设计

对内提效类与对外变现类的**客户、价值主张、计费逻辑完全不同**，混在一张表里必然设计不清。

| | 对内提效类 | 对外变现类 |
|---|---|---|
| 客户 | 集团及下属公司 | 外部机构（政府/企业/金融机构） |
| 价值主张 | 省人力、提时效、消争议 | 提供别人拿不到的数据 |
| 计费 | 不收费（成本中心） | 按调用/订阅/授权 |
| 成败标准 | 内部使用率 | 收入或影响力 |
| **风险** | 建了没人用 | **合规与确权**（高得多） |

## 一、对内提效类（7 个）

## 二、对外变现类（4 个）

| 编号 | 产品 | 目标客户 | 变现方式 | 数据来源 | **凭什么我们能做（独特性）** | 优先级 |
|---|---|---|---|---|---|---|
| E-01 | **农产品价格指数** | 政府/行业/金融机构 | 授权发布 + 品牌影响力 | 集团多市场价格明细 | **多市场实际成交价**（非报价、非抽样），且**跨 6 家市场** | **P0（战略）** |
| E-02 | 区域农产品供需报告 | 政府/涉农企业 | 售卖/订阅 | 进场量+交易量+价格 | 真实的**进场-交易-流向**全链路数据 | P1 |
| E-03 | 产销对接数据服务 | 产地/采购商 | 按调用/订阅 | 商户画像+品种流向 | 掌握**买方侧真实采购行为** | P2（依赖 One ID） |
| E-04 | 数据源授权 | 数据商/交易所 | 一次性/分成 | 脱敏后的价格/供需 | 数据稀缺性 | P2 |

### 为什么 E-01 是战略级
- 呼应集团主线：**从"市场运营商"→"行业数据源"**，指数是行业话语权的具象载体。
- 政策窗口：地方数字经济与"数据要素×现代农业"政策支持。
- **但必须有前置**：单位统一 + 跨区域数据源 + 指数方法论 + 公信力建设。**不能直接跳到发布**。

## 五、挂回七道工序（门禁-挂接性）

| 产品编号 | 归属工序 | 说明 |
|---|---|---|
| I-01 经营日报 | **服 + 用** | 服务层输出、应用层消费 |
| I-02 经营驾驶舱 | **用** | 应用层 |
| I-03 价格监测预警 | **用 + 模** | 预警规则属模型算法（模） |
| I-04 商户统一视图 | **治 + 管** | 主数据属治、目录权限属管 |
| I-05 冷库温控看板 | **用** | 应用层 |
| I-06 报表自动分发 | **服** | 服务共享 |
| I-07 招采价格对比 | **用** | 应用层 |
| E-01 农产品价格指数 | **用 + 模** | 指数属模型算法，发布属应用 |
| E-02 区域供需报告 | **用** | 应用层 |
| E-03 产销对接数据服务 | **服** | 对外的数据服务 |
| E-04 数据源授权 | **管 + 服** | 资产授权属管、交付属服 |

**工序分布小结**：用（6）/ 服（3）/ 治（1）/ 管（2）/ 模（2）—— **服用模三工序为主**，与立项范围一致 ✅
