# 案例：集团A（虚构）— 摸底摘要（baseline-summary）

> 完全虚构，仅示范格式。只写量级与结论，禁细节。

## 一、系统摸排结果
- **系统数量级**：10+ 套业务系统
- **系统类型分布**：
  - 自研：交易结算系统、门户系统（2 套）
  - 采购：财务系统、人力系统、OA（3 套）
  - 硬件/物联网：门禁道闸、地磅称重、电子交易屏（多套）
  - **离线 Excel 台账**：各市场自行维护的商户台账、摊位台账（**未纳入任何系统清单，是最大盲区**）
- **关键发现（抽象化）**：
  - 主数据分散在 3 套系统，无权威源
  - 2 套系统自称"商户数据的唯一来源"
  - 电子交易屏数据与结算系统对不上，差异原因无人能解释

## 二、数据资产规模
- **库表量级**：百级表
- **字段量级**：千级字段
- **离线数据源**：有，各市场 Excel 台账分散存在本地电脑（未统一管理）

## 四、摸底方法论要点
- **先盘系统后盘数据**：先花 3 天跟 IT 现场盘系统，再发问卷（顺序关键）
- **脚本扫描 + 问卷核对的配合**：
  - 先用扫描脚本枚举数据库表/字段 + Excel 台账文件
  - 再发问卷核对字段业务含义与口径
  - 交叉校验发现 30+ 个"孤儿表"（脚本扫到但无人认领）
- **最大障碍**：各市场负责人对"数据归属"敏感，担心盘点后失去数据控制权 → 通过"数据所有权仍在业务、平台只做统一编目"化解

## 五、教训（gotchas）

1. **先盘系统后盘数据**
   初期先发问卷导致返工一轮：问卷回收后发现系统边界未明，跨系统字段完全对不上。正确顺序是先摸清系统清单。
   → 已回写 SKILL.md。

2. **主数据唯一标识缺失**
   "商户"在交易系统/门户系统/财务系统各有一套 ID，同一商户被算成三个，导致商户总数虚高。
   必须先定权威源与唯一标识。

3. **影子数据源（Excel 台账）是最大盲区**
   最初系统清单里没有 Excel 台账，盘点后才发现各市场用 Excel 维护商户与摊位信息——这是真实业务的关键数据源，却完全脱离管控。

4. **"两个系统都自称唯一真相源"**
   交易系统与门户系统都声称商户数据以自己为准。这类冲突必须在摸底阶段就记录并上报，不能默认放过。

5. **摸底阶段不做治理**
   盘点中发现大量质量问题，但严格记录不修——修复属于后续质量阶段，摸底时顺手改会拖长工期且无优先级依据。

6. **敏感级别要当场标定**
   初期未标敏感级别，导致后续架构设计阶段无法做访问控制，需要回头补标。
