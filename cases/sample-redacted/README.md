## 集团A（虚构）— 区域农批市场集团

- **行业类别**：农产品批发市场集团（虚构）
- **规模档**：营收十亿级（虚构，仅作量级示范）
- **数据现状初判**：10+ 套业务系统，百级库表，主数据分散在 3 套系统

### 交付范围
覆盖七道工序：汇 / 存 / 治 / 管 / 服 / 用（未含"模"）
覆盖技能：dx-data-baseline → dx-architecture-opt → dx-data-quality → dx-application-plan
交付周期：6 周（虚构）

### 结果概览（虚构）
- DCMM 成熟度：受管理级（2 级）→ 稳健级（3 级）方向
- 入典核心指标：20 个（虚构）
- 采纳情况：三阶段路线图被采纳，阶段一启动

### 关键教训（抽象化，可复用）
1. **先盘系统后盘数据**：初期先发问卷，回收后发现系统边界未明，导致跨系统字段对不上，返工一轮。正确顺序是先摸清系统清单。
2. **主数据唯一标识缺失**："客户"在交易系统/会员系统/财务系统各有一套 ID，导致同一客户被算成三个。必须先定权威源。
3. **指标口径冲突**："交易额"在业务口径与财务口径下相差显著（是否含税、是否含退货），建指标字典后争议消解。
4. **不要先建大平台**：集团初期期望直接上中台，经评估建议先补"汇存治"地基，避免中台变成数据垃圾场。

> 以上教训均为虚构示范，用于说明 `cases/` 的填写格式与深度。
