# 案例层（Cases Layer）接口规范

> 本套件把"方法论/技能层"与"真实案例层"**物理隔离**。
> 技能层开源可分发；案例层由使用者自行填充（**不得提交客户机密数据**）。

## 为什么隔离
- 交付型套件的说服力来自真实案例，但真实案例常含客户机密。
- 因此：**接口开源、内容自填**。你可以在私仓/本地维护案例，公开仓只放格式与脱敏样例。

## 目录约定
```
cases/
├── README.md                 # 本文件（接口规范）
├── _template/                # 空白模板（开源）
│   ├── engagement.md         # 项目概况模板
│   ├── baseline-summary.md   # 摸底摘要模板
│   ├── architecture-summary.md
│   ├── quality-summary.md
│   └── application-summary.md
├── sample-redacted/          # 脱敏样例（开源，虚构或去标识）
│   └── ...                   # 仅作格式示范，非真实客户
└── <your-case-01>/           # 你的私有案例（.gitignore 排除）
    └── ...
```

## 案例包标准结构（每个案例一套）
| 文件 | 内容 | 是否可开源 |
|---|---|---|
| `engagement.md` | 行业/集团类型/规模档/交付范围 | 脱敏后可 |
| `baseline-summary.md` | 资产规模量级（如"10+ 系统、百级表"）、成熟度分 | 仅量级，禁细节 |
| `architecture-summary.md` | 蓝图要点、阶段划分 | 脱敏后可 |
| `quality-summary.md` | 指标字典样例（虚构指标）、规则类型 | 脱敏后可 |
| `application-summary.md` | 场景类型、价值量化口径 | 脱敏后可 |
| `gotchas.md` | **本项目踩坑（最有价值）** | 脱敏后可 |

## 脱敏规则（强制）
1. **禁**：真实企业名、系统名、表名字段名、金额绝对值、人员姓名、任何可反推标识。
2. **可**：行业类别（如"农批市场集团"）、规模档（"营收百亿级"）、方法论要点、抽象化教训。
3. 用**虚构编号**替代主体：如 `集团A`、`系统S1`、`表T01`。
4. 提交前自检：**"外人能否通过组合信息定位到具体企业？"** 能则再脱敏。

## 使用方式（技能如何调用案例）
- `dx-engagement-orchestrator` 启动时**先探测 `cases/` 是否非空**：
  - 有案例 → 参考同类案例的量级与方法，加速本次交付。
  - 无案例 → 走通用路径，交付后按本规范沉淀新案例。
- 案例**不作为硬依赖**：技能层脱离案例层必须能独立运行。

## 你的补充路径（建议）
1. 先放 1 个**脱敏样例**（虚构集团）跑通格式。
2. 每完成一个真实项目 → 按模板沉淀 → 判断可否脱敏开源。
3. 形成"行业 × 案例"矩阵后，套件的说服力与检索价值成倍上升。
