# 案例库保密机制说明

> 给使用者（含非技术背景）看的说明。**案例库默认完全保密**，不联网、不共享、不上传。

---

## 一、先明确：案例库就是你本地的一个文件夹

```
K:\workbuddy\星级SKILL- gihub\data-element-dx-skillkit\cases\
```

案例就是**文件夹**，不是数据库、不是云服务。你不主动上传/分享，就没有任何人能看到。

---

## 二、所谓"接口"是什么？

**不是云数据库接口，不是 API。**

"接口"在这里指**一套填写格式约定**——规定每个案例文件夹里放哪几个文件、每个文件写什么内容。就像：

> 填表格要有固定栏目：姓名/年龄/地址。你按栏目填，别人（这里是 AI 技能）就能读懂。

约定如下（每个案例一套）：

| 文件名 | 写什么 |
|---|---|
| `engagement.md` | 项目概况：行业类别、规模档、交付范围、约束 |
| `baseline-summary.md` | 摸底摘要：系统量级、资产规模、成熟度分、教训 |
| `architecture-summary.md` | 架构要点：蓝图、路线图、治理卡口情况 |
| `quality-summary.md` | 质量摘要：指标字典统计、规则数、访问边界 |
| `application-summary.md` | 应用摘要：场景地图、数据产品、入表路径 |

**好处**：技能读到任何案例都自动知道去哪找什么，你不用每次解释。格式统一也让案例能被检索、对比、复用。

---

## 三、保密三道闸门

### 闸门 1｜物理隔离
- 技能层（`dx-*/`、`_shared/`）→ 设计为可开源
- 案例层（`cases/`）→ 默认私有

两层分开存放，公开技能不会连带暴露案例。

### 闸门 2｜`.gitignore` 自动拦截
`.gitignore` 已配置：

```gitignore
cases/*/                    # 排除所有案例文件夹
!cases/_template/           # 保留：空白模板
!cases/sample-redacted/     # 保留：虚构样例
```

**效果**：将来你若用 git 上传到 GitHub，`cases/` 下的私有案例**不会被提交**——git 视它们如不存在。
你在本地照常读写，上传时自动跳过。

### 闸门 3｜脱敏规则（决定哪些能公开）
即使你想公开某案例，也必须遵守：

| 禁止 | 替换为 |
|---|---|
| 真实企业名 | `集团A`、`集团B` |
| 真实系统名 | `系统S1`、`交易系统` |
| 真实表名/字段名 | `表T01` |
| 金额绝对值 | 量级描述（"十亿级"） |
| 人员姓名 | 角色（"财务负责人"） |

**自检标准**：外人能否通过组合信息定位到具体企业？能，就再脱敏。

## 四、三种保密强度（自行选择）

| 方案 | 做法 | 适用场景 | 风险 |
|---|---|---|---|
| **A. 全私有**（推荐起步） | 案例只放本地，除模板与虚构样例外一律不上传 | 含明确客户机密 | 最低 |
| **B. 私有仓分离** | 公开仓只放技能+模板；真实案例放独立私有 git 仓 | 需版本管理但不上公网 | 低 |
| **C. 脱敏后公开** | 单案例按规则脱敏，人工复核后加入公开仓 | 需案例增强说服力 | 中（依赖脱敏质量） |

**建议**：先 A，用顺了再考虑 C。**原始案例永远只在本地。**

## 五、常见疑问

**Q：我用 WorkBuddy 时，案例会被上传吗？**
A：不会。WorkBuddy 读写的是你本地文件；是否上传取决于你是否用 git 推送或手动分享。

**Q：`sample-redacted` 里的"集团A"会不会被误认为真实客户？**
A：不会，文件头已明确标注"完全虚构"，且用了明显虚构的代号。

**Q：我想给客户看案例，怎么办？**
A：用"方案 B"的私有仓，或临时导出一份脱敏副本单独发送，不要从公开仓取。

**Q：如果我不碰 git，只是本地用呢？**
A：那保密天然成立——文件在你 K 盘，不联网不共享。`.gitignore` 只是为将来上传兜底。

**Q：案例能加密吗？**
A：可以（如 7-Zip AES-256 打包），但会增加使用成本。一般"私有文件夹 + 不上传"已足够。

---

## 六、你要做的只有一件事

**把真实案例写进 `cases/<你的案例名>/`，其余不管。** 上传时 git 会自动跳过。
